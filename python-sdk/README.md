# INFO-Subscription Python SDK

Python client for the [INFO-Subscription API](https://api.info-subscription.com), generated by [Kiota](https://github.com/microsoft/kiota) with Azure AD B2C authentication plumbing.

## Installation

```bash
pip install infosoft-info-subscription
```

## Requirements

- Python 3.10+

## Usage

```python
import asyncio
from info_subscription_sdk import (
    create_info_subscription_client,
    InfoSubscriptionSettings,
    B2CAuthSettings,
)

client = create_info_subscription_client(
    InfoSubscriptionSettings(
        tenant_id="your-tenant-guid",
        auth=B2CAuthSettings(
            client_id="your-client-id",
            client_secret="your-client-secret",
            b2c_tenant_name="yourb2ctenant",
            # sign_in_policy="B2C_1A_V2SIGNIN",  # default
            # scope_name="api",                   # default
        ),
        # api_endpoint="https://api.info-subscription.com",  # default
    )
)

async def main():
    products = await client.product.get()
    for p in products:
        print(p.name)

asyncio.run(main())
```

## Configuration

| Field | Type | Default | Description |
|---|---|---|---|
| `tenant_id` | `str` | required | Tenant GUID — sent as `S4-TenantId` on every request |
| `auth.client_id` | `str` | required | Azure AD B2C application (client) ID |
| `auth.client_secret` | `str` | required | Azure AD B2C client secret |
| `auth.b2c_tenant_name` | `str` | required | B2C tenant name (e.g. `"mycompany"`) |
| `auth.sign_in_policy` | `str` | `"B2C_1A_V2SIGNIN"` | B2C sign-in policy |
| `auth.scope_name` | `str` | `"api"` | API scope name |
| `api_endpoint` | `str` | `"https://api.info-subscription.com"` | API base URL |

## Authentication

Authentication uses the [OAuth 2.0 client credentials flow](https://learn.microsoft.com/en-us/azure/active-directory/develop/v2-oauth2-client-creds-grant-flow) against an **Azure AD B2C** tenant.

The SDK handles:
- Token acquisition via `msal.ConfidentialClientApplication`
- Token caching (in-memory, handled by MSAL)
- Automatic token refresh on expiry
- Injecting `Authorization: Bearer <token>` on every request
- Injecting `S4-TenantId` on every request

## Architecture

```
create_info_subscription_client(settings)
    └── ConfidentialClientAuthenticationProvider   ← MSAL B2C token acquisition
    └── BaseBearerTokenAuthenticationProvider      ← Kiota auth wrapper
    └── TenantHeaderMiddleware                     ← adds S4-TenantId header
    └── KiotaClientFactory (default middlewares)   ← retry, redirect, etc.
    └── HttpxRequestAdapter                        ← async HTTP via httpx
    └── InfoSubscription(adapter)                  ← Kiota-generated client
```

## Generated code

The `src/info_subscription_sdk/generated/` folder is **auto-generated** by Kiota from the INFO-Subscription OpenAPI spec. Do not edit it manually — changes will be overwritten by the `azure-pipeline.yml` SDK regeneration pipeline.
